## 2. Yang diperbaiki

### P0 — Fungsional
1. **Tema tidak tersimpan.** `app.js` menulis `localStorage['stockforge-theme']`, sementara layout & `theme-toggle.js` membaca `sf-theme`. Akibatnya tema kembali ke terang setiap muat ulang. Kini satu kunci kanonik `sf-theme` + migrasi otomatis dari kunci lama.
2. **Tombol aksi terpotong di mobile** (`/user-rules`): toolbar `display:flex` tanpa `flex-wrap` di dalam kartu `overflow:hidden`. Kini membungkus di ≤760 px.

### P1 — Aksesibilitas
3. **Skip-link** "Lewati ke konten utama" ditambahkan di semua halaman (`#main-content` + `tabindex="-1"`).
4. **Focus visible**: cincin fokus 3 px untuk semua kontrol; topbar (`outline:none` tanpa pengganti) kini punya indikator jelas.
5. **Kontras teks**: `#94a3b8` (2,56:1) dan `#7b8798` (3,65:1) diganti token `--sf-muted-ink` (7,5:1) / `--sf-subtle-ink` (5,6:1). Pil status hijau 2,98:1 → 4,8:1; tombol *success* 3,12:1 → 5,0:1; segmented view-mode 3,56:1 → 7,1:1.
6. **Gradient hero**: stop akhir terlalu terang (putih di atas `#f093fb` = 1,8:1). Semua 14 tone digelapkan sehingga setiap stop ≥ 4,9:1 terhadap teks putih.
7. **Target sentuh**: kontrol topbar & paginasi minimum 44×44 px di layar sentuh.
8. **Nama aksesibel**: panel `role="listbox"` pada komponen `sf-select` kini punya `aria-label` (dari `aria-label` select → `<label for>` → opsi pertama).
9. **Struktur ARIA**: `role="tablist"` pada chip filter (tanpa `role="tab"`) diubah ke `role="group"` + `aria-pressed`; pil view-mode jadi `role="region"`; heading `h3` di Jejak Proses → `h2`; tombol pemindai tersembunyi tidak lagi fokusable.

## 1. Akar masalah: token kontras tidak sampai ke browser

`tokens.css` di disk sudah benar (`--success-text: #0b7a56`, 4,8:1), tetapi browser tetap menghitung `#0ca678` (3,2:1). Penelusuran:

- CSS dari origin (`127.0.0.1:8331`) → nilai baru.

## 2. Preview Marking Memo — bug dokumen, bukan sekadar kontras

`/items/memo/preview` dirender dengan `$this->view('items/memo', [...], null)` — layout `null` berarti `View::render()` mengembalikan potongan HTML mentah tanpa `<html>`, `<head>`, maupun `<title>`. Yang sampai ke browser:

- tanpa doctype → **quirks mode** (`document.compatMode` = `BackCompat`);
- tanpa `<html lang>` → pelanggaran `html-has-lang`;
- tanpa `<meta charset>` → encoding bergantung tebakan browser;
- `<title>` jatuh ke nama aplikasi saja ("🐴");

Perbaikan di `app/Views/items/memo.php`: saat `$isPdf === false`, view kini mengeluarkan dokumen utuh (doctype, `lang`, charset, viewport, title, favicon) dan memuat tumpukan CSS yang sama dengan halaman aplikasi — `tokens.css`, `app.css`, `sf-ui.css`, `flat-material.css`, `a11y-fixes.css`, `a11y-pass2.css` — lalu `<style>` memo. Urutan ini penting: gaya memo tetap menang karena dirender terakhir.

Jalur PDF tidak disentuh: `$isPdf === true` tetap memakai cabang lama (`standalone`), sehingga Dompdf menerima HTML yang sama seperti sebelumnya.

Efek samping yang ikut hilang: tombol "Unduh PDF halaman ini" memakai `.btn-brand` yang di preview jatuh ke gaya `app.css` mentah — teks `#1864ab` di atas amber `#f0b429` = **3,27:1** (gagal AA). Dengan tumpukan CSS lengkap, tombol memakai biru `#2563eb` + teks putih = **5,17:1**.

# Pass 4 — 18 Oktober 2026: grafik Report hilang

**Laporan pengguna:** menu Report tidak menampilkan grafik — kartu "Tren nilai selisih per tahun buku" kosong, hanya menyisakan garis pemisah dan secuil batang merah di kiri.

## Penyebab

`app.css:2431` memasang *safety net* global untuk ikon:

```css
svg { width: 16px; height: 16px; flex: 0 0 auto; }
```

Aturan ini menang atas atribut presentasi `width="360" height="208"` pada `<svg>` grafik, karena CSS selalu mengalahkan atribut SVG. Inline style di `reports/index.php` hanya menyetel `max-width:100%;height:auto`, **tidak** menyetel `width`, sehingga grafik dirender 16px lebar dan tingginya menyusut ke 9px mengikuti rasio 360:208.

Terukur di browser sebelum perbaikan:

```
svg 16 × 9 px   (atribut width=360 height=208)
parent 917 × 9 px
batang pertama 2 × 1 px
```

Bukan masalah data: `$chart` berisi 4 periode dan SVG-nya lengkap di HTML (4 `<rect>`, 12 `<text>`).

## Perbaikan

`app/Views/reports/index.php`:

1. `width` eksplisit di inline style — inline menang atas `svg{width:16px}`:
   `style="width:<?= $vw ?>px;max-width:100%;height:auto;display:block;margin-inline:auto;"`
2. `class="sf-chart"` untuk selektor pertahanan.
3. Jarak antar batang adaptif: `$gap = 36 + (6 - $n) * 22` bila periode < 6, supaya grafik tidak menyusut jadi kolom sempit saat periodenya sedikit (4 periode → `$vw` 576, bukan 360).

`a11y-pass2.css` — pengaman agar SVG grafik tidak pernah dikunci 16px lagi:

```css
svg.sf-chart { width: auto; height: auto; flex: 0 1 auto; }
@media print { svg.sf-chart { max-width: 100% !important; } }
```

# Pass 5 — 18 Oktober 2026: pil pemilih tampilan auto-hide saat menggulir

**Permintaan pengguna:** pil "Tampilan / Otomatis / Kartu / Tabel" (`.sf-vm`) yang `position:fixed` di kanan bawah menutupi sudut kanan-bawah grafik/kartu. Tambahkan auto-hide saat menggulir.

## Perilaku yang dipilih

Pola toolbar browser mobile, tanpa timer "muncul sendiri":

| Kejadian | Pil |
|---|---|
| Halaman dimuat / di posisi atas (≤120px) | tampil |
| Menggulir ke bawah (>8px) | **menyingkir** |
| Menggulir ke atas (>8px) | tampil |
| Berhenti membaca di tengah halaman | tetap menyingkir |
| Sampai dasar halaman (≤60px dari bawah) | tampil (di sana ada ruang `.sf-vm__spacer`) |
| Fokus keyboard masuk ke pil | tampil |
| `resize` / rotasi layar | tampil |

Sengaja **tidak** ada timer "muncul lagi setelah N ms": kalau pil muncul sendiri saat pengguna berhenti membaca, ia menutupi grafik lagi — persis masalah yang dilaporkan. Untuk memunculkan, cukup geser ke atas sedikit.

## Implementasi

`public/assets/css/sf-viewmode.css`

```css
.sf-vm { transition: transform .24s cubic-bezier(.4,0,.2,1), opacity .18s ease; will-change: transform; }
.sf-vm.is-tucked { transform: translateY(calc(100% + 28px)); opacity: 0; pointer-events: none; }
@media (prefers-reduced-motion: reduce) {
  .sf-vm { transition: opacity .14s linear; }
  .sf-vm.is-tucked { transform: none; }
}
```

`public/assets/js/sf-viewmode.js` — `initAutoHide()`, dipanggil dari `boot()` setelah `place()`.

Poin teknis yang penting:

1. **Throttle pakai `setTimeout(60)`**, bukan `requestAnimationFrame`. rAF berhenti total saat tab tidak terlihat; dengan pola `if (raf) return; raf = rAF(...)`, antrean terkunci selamanya dan pil tidak pernah menyingkir lagi. Ini sempat terjadi saat pengujian.
2. **Target scroll dideteksi dari event**, bukan diasumsikan `window`. Di desktop yang menggulir `html`, di layout mobile yang menggulir justru `body` (`body{height:100%;overflow:auto}`), sehingga `window.pageYOffset` selalu 0 di mobile. Listener dipasang `document … {capture:true}` supaya scroll pada kontainer ber-overflow ikut tertangkap.
3. **Posisi terakhir disimpan per elemen** (`el.__sfVmY`) dan disemai saat init, supaya lompatan gulir pertama (PageDown, anchor, restore posisi) tetap terbaca sebagai arah — bukan dianggap "tidak bergerak".
4. `pointer-events:none` saat tersembunyi, dan `focusin` memunculkannya kembali agar pengguna keyboard tidak kehilangan kontrol.

# Pass 6 — 18 Oktober 2026: tombol sembunyikan / tampilkan pil

**Permintaan pengguna:** selain auto-hide, sediakan cara manual untuk menyembunyikan dan memunculkan pil.

## Yang ditambahkan

| Elemen | Fungsi |
|---|---|
| Chevron-down di ujung kanan pil (`.sf-vm__collapse`) | menyingkirkan seluruh pil; fokus pindah ke tombol bulat |
| Tombol bulat 44px di sudut (`.sf-vm-handle`) | memunculkan pil kembali; fokus pindah ke mode yang sedang aktif |
| `localStorage['sf-vm-collapsed']` | mengingat pilihan antar halaman dan saat reload |

Saat pil disembunyikan, yang tersisa hanya tombol bulat 44×44 di sudut kanan-bawah — cukup kecil untuk tidak menutupi grafik, cukup besar untuk disentuh (di atas ambang 24px WCAG 2.5.8).

## Detail teknis

1. **`visibility:hidden` + `inert`**, bukan sekadar `opacity:0`. Tanpa itu tombol-tombol di dalam pil tetap bisa dijangkau Tab meski tak terlihat (perangkap fokus). Diuji: saat collapsed, tidak ada satu pun elemen fokus di dalam `.sf-vm` (114 elemen fokus di halaman, nol dari pil).
2. **`inert` dipasang/ dilepas bersamaan**, dan `aria-expanded` pada tombol bulat menunjukkan keadaan.
3. **Fokus dikelola**: mengecilkan → fokus ke tombol bulat; membuka → fokus ke tombol mode yang sedang aktif (`[aria-pressed="true"]`), bukan ke `body`.
4. **Auto-hide tidak melawan keadaan manual**: `show()`/`hide()` tidak menyentuh kelas `is-tucked` selama `is-collapsed` aktif.
5. **Tombol bulat ikut naik** kalau ada `.bottom-action-bar` (mis. halaman Items di mobile): `place()` memberi offset yang sama pada pil dan tombol, plus `env(safe-area-inset-bottom)`.

# Pass 11 — 18 Oktober 2026: popup filter hanya tampil 1 baris

## Gejala
Popup "Filter: Kode" hanya menampilkan **1 baris** checkbox (baris kedua
terpotong) walau isinya 39 nilai. Terukur sebelum perbaikan:

```
pop.height = 238px (inline maxHeight 238px)
list.height = 50px   (scrollHeight 120px)  → 1,25 baris
```

## Akar masalah — tinggi "self-fulfilling"
`placePop()` mengukur tinggi popup dengan `pop.offsetHeight`, padahal
`pop.style.maxHeight` hasil pemanggilan **sebelumnya** masih terpasang.
Saat popup dibuka, daftar masih berisi "Memuat..." (tinggi kecil), jadi
`maxHeight` dikunci di angka kecil itu. `render()` memanggil `reposition()`
→ `placePop()` lagi, tapi `offsetHeight` yang terbaca **sudah terpotong
oleh maxHeight lama** → nilainya sama terus, popup tidak pernah tumbuh.
Akibatnya `flex:1` pada `.xf-list` menghimpit daftar jadi ~50px.

## Perbaikan (3 file, logika sama)
`app/Views/items/index.php`, `app/Views/reconciliation/index.php`,
`app/Views/partials/colfilter.php` (dipakai 10 menu: audit, audit/history,
users, groups, activity, discrepancies, devices, warehouses, locations,
master_data).

1. **Ukur tinggi natural tanpa batas** sebelum menghitung:
   `pop.style.maxHeight='none'` + `list.style.maxHeight='none'`, baca
   `pop.offsetHeight` dan `list.offsetHeight`, lalu hitung
   `chrome = natural − listNatural` (kepala + kolom cari + tombol urut + footer).
2. **Batasi daftar, bukan popup**: `list.maxHeight = clamp(space, 120, 300)`
   → minimum 3 baris, maksimum 7 baris; popup sendiri `overflow:hidden`
   sehingga tombol Batal/Terapkan tidak pernah ikut ter-scroll.
3. **Pilih sisi yang muat** (bawah vs atas) berdasarkan kebutuhan nyata
   `chrome + daftar`, bukan angka `h` basi; kalau sisi terpilih sempit,
   pindah ke sisi yang lebih lega.
4. Popup varian **range** (rekonsiliasi) memakai tinggi natural yang sama
   dan hanya membatasi diri kalau ruang benar-benar kurang.
5. Jaring pengaman: kalau viewport lebih pendek dari tinggi popup,
   `maxHeight = vh − 16` + `overflow:auto` (baru popup yang scroll).
